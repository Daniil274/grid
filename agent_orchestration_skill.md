# Skill: Координатор конвейера агентов (beads + orchestrate)

## 1. Назначение
Этот skill обучает координатора работать через последовательный конвейер специализированных агентов. Цель — не выполнять нетривиальную работу в одиночку, а строить проверяемый процесс через `beads` как шину данных и `orchestrate` как механизм запуска агентов.

Skill применяй, когда нужно:
- изучать кодовую базу или документацию;
- писать файл на основе анализа проекта;
- синтезировать инструкции, skill, prompt, тест-план, спецификацию;
- сверять результат по нескольким источникам;
- изменять существующие файлы.

Если пользователь явно просит «без агентов», можно работать напрямую. Иначе для нетривиальных задач конвейер обязателен.

## 2. Правило тривиальности
### Тривиальная задача
Можно ответить самостоятельно, если одновременно верно следующее:
- не нужно изучать проект или документацию;
- не нужно менять файлы;
- не нужно сверять несколько источников;
- ответ можно дать сразу, без промежуточной проверки.

Примеры:
- кратко объяснить термин;
- ответить на уточняющий вопрос;
- предложить один небольшой текстовый вариант без анализа проекта.

### Нетривиальная задача
Нужно строить конвейер через beads, если выполняется хотя бы одно условие:
- требуется анализ файлов, кода, документации;
- требуется создать или изменить файл;
- требуется подготовить инструкцию, skill, prompt, тест-план или спецификацию;
- требуется проверка несколькими шагами или из нескольких источников.

## 3. Обязательный минимум конвейера
Для любой нетривиальной задачи минимальный паттерн такой:
1. **Агент-сборщик контекста**
2. **Агент-исполнитель**
3. **Агент-верификатор**

Связь между агентами идёт только через beads.
Агент A не передаёт результат агенту B напрямую: он пишет результат в `notes`, следующий агент читает его через `beads_show()`.

## 4. Роль beads и базовый протокол
`beads` — это персистентная шина данных между агентами.

### Координатор обязан сделать до запуска агентов
1. Создать bead-задачи заранее через `beads_create()`.
2. При необходимости связать их зависимостями через `beads_dep()`.
3. Только после этого запускать агентов через `orchestrate()`.

### Каждый агент обязан
1. Начать с `beads_show('BEAD_ID')`.
2. Прочитать описание задачи и `notes` от предыдущих агентов.
3. Выполнить свою часть работы.
4. Записать структурированный результат через `beads_update('BEAD_ID', notes='...')`.

### Минимальный протокол записи
- `[CONTEXT] РЕЗУЛЬТАТ: ...`
- `[AUTHOR] РЕЗУЛЬТАТ: ...`
- `[VERIFY] ВЕРИФИКАЦИЯ: PASS/FAIL ...`
- `[ROLE] ПРОБЛЕМА: ...`

## 5. Выбор паттерна конвейера
### Паттерн A — Исполнитель → Верификатор
Используй для простой, но всё же нетривиальной задачи, где отдельный сбор контекста почти не нужен.

Подходит для:
- небольшого исправления;
- точечного изменения файла;
- локальной генерации текста по уже понятному контексту.

### Паттерн B — Контекст → Исполнение → Верификация
Это базовый и предпочтительный паттерн.

Подходит для:
- анализа проекта;
- подготовки документации;
- создания skill/prompt/spec;
- изменений, где сначала надо изучить текущую структуру.

### Паттерн C — Fan-out / Fan-in
Используй, когда есть несколько независимых частей.

Подходит для:
- анализа разных модулей;
- подготовки нескольких независимых артефактов;
- сборки результата из нескольких отдельных исследований.

## 6. Пошаговый алгоритм координатора
1. **Классифицируй задачу**
   - тип: исследование / создание / исправление / рефакторинг / смешанная;
   - масштаб: атомарная / составная / комплексная;
   - риски: изменения файлов, неоднозначные требования, необходимость верификации.

2. **Проверь, тривиальна ли задача**
   - если да — ответь сам;
   - если нет — переходи к конвейеру.

3. **Создай beads до запуска агентов**
   - отдельный bead для контекста;
   - отдельный bead для исполнения;
   - отдельный bead для верификации.

4. **Настрой зависимости**
   - `implement` зависит от `context`;
   - `verify` зависит от `implement`.

5. **Запусти агентов последовательно через `orchestrate()`**
   - агент 1 читает свой bead и пишет результат;
   - агент 2 читает свой bead и bead контекста;
   - агент 3 читает bead исполнения и проверяет итог.

6. **Прочитай итог сам через `beads_show()`**
   - проверь notes;
   - убедись, что есть результат и верификация.

7. **Сохрани финальный артефакт или отчёт**
   - при необходимости обнови файл;
   - при необходимости закрой bead через `beads_close()`.

## 7. Требования к формированию задачи для агента
При вызове `orchestrate()` у каждого агента должны быть три вещи:

### 7.1. `task`
В `task` обязательно укажи:
- конкретный `bead_id`;
- что нужно прочитать через `beads_show()`;
- что именно нужно сделать;
- куда и в каком формате писать результат через `beads_update()`.

Хороший шаблон:
```text
Выполни задачу из bead BEAD_ID.
1) Начни с beads_show('BEAD_ID').
2) Прочитай описание и notes.
3) Выполни работу.
4) Запиши результат через beads_update('BEAD_ID', notes='[ROLE] РЕЗУЛЬТАТ: ...').
5) Если есть проблема — beads_update('BEAD_ID', notes='[ROLE] ПРОБЛЕМА: ...').
```

### 7.2. `agent_system_prompt`
В системном промпте обязательно укажи:
- роль агента;
- краткую специализацию;
- протокол работы через beads;
- требование начать с `beads_show()`;
- требование закончить `beads_update()`.

Хороший шаблон:
```text
Ты агент-верификатор.
ПРОТОКОЛ КОММУНИКАЦИИ:
1. Начни с beads_show('BEAD_ID').
2. Прочитай задачу и notes от предыдущих агентов.
3. Выполни проверку.
4. Запиши вердикт через beads_update('BEAD_ID', notes='[VERIFY] ВЕРИФИКАЦИЯ: PASS/FAIL ...').
```

### 7.3. `executor_tools`
Для агента обязательно добавляй:
- `beads_show`
- `beads_update`

Дополнительно — только нужные рабочие инструменты, например:
- `filesystem`
- `terminal`
- `beads_create`
- `beads_dep`

Пример правильного набора:
```text
["filesystem", "terminal", "beads_show", "beads_update"]
```

Важно: передавай именно ключи инструментов, а не низкоуровневые названия функций.

## 8. Шаблоны координатора
### 8.1. Создание beads
```text
beads_create(
  title="Сбор контекста для задачи X",
  type="task",
  priority=1,
  description="Изучить проект и записать структурированный контекст в notes bead."
)

beads_create(
  title="Реализация задачи X",
  type="task",
  priority=1,
  description="На основе bead контекста выполнить работу и записать результат в notes."
)

beads_create(
  title="Верификация задачи X",
  type="task",
  priority=1,
  description="Проверить результат исполнения и записать вердикт в notes."
)
```

### 8.2. Установка зависимостей
```text
beads_dep(action="add", child_id="BD-IMPL", parent_id="BD-CTX")
beads_dep(action="add", child_id="BD-VERIFY", parent_id="BD-IMPL")
```

### 8.3. Агент-сборщик контекста
```text
orchestrate(
  task="Выполни задачу из bead BD-CTX. Начни с beads_show('BD-CTX'). Изучи нужные файлы проекта. Запиши результат через beads_update('BD-CTX', notes='[CONTEXT] РЕЗУЛЬТАТ: ...').",
  agent_system_prompt="Ты агент-сборщик контекста. ПРОТОКОЛ: 1) beads_show('BD-CTX'); 2) изучи материалы; 3) beads_update('BD-CTX', notes='[CONTEXT] РЕЗУЛЬТАТ: ...').",
  executor_tools=["filesystem", "beads_show", "beads_update"]
)
```

### 8.4. Агент-исполнитель
```text
orchestrate(
  task="Выполни задачу из bead BD-IMPL. Начни с beads_show('BD-IMPL'). Затем прочитай beads_show('BD-CTX'). Выполни работу и запиши итог через beads_update('BD-IMPL', notes='[AUTHOR] РЕЗУЛЬТАТ: ...').",
  agent_system_prompt="Ты агент-исполнитель. ПРОТОКОЛ: 1) beads_show('BD-IMPL'); 2) beads_show('BD-CTX'); 3) выполни работу; 4) beads_update('BD-IMPL', notes='[AUTHOR] РЕЗУЛЬТАТ: ...').",
  executor_tools=["filesystem", "terminal", "beads_show", "beads_update"]
)
```

### 8.5. Агент-верификатор
```text
orchestrate(
  task="Проверь результат из bead BD-IMPL. Начни с beads_show('BD-VERIFY'). Затем прочитай beads_show('BD-IMPL') и при необходимости beads_show('BD-CTX'). Запиши вердикт через beads_update('BD-VERIFY', notes='[VERIFY] ВЕРИФИКАЦИЯ: PASS/FAIL ...').",
  agent_system_prompt="Ты агент-верификатор. ПРОТОКОЛ: 1) beads_show('BD-VERIFY'); 2) beads_show('BD-IMPL'); 3) выполни проверку; 4) beads_update('BD-VERIFY', notes='[VERIFY] ВЕРИФИКАЦИЯ: PASS/FAIL ...').",
  executor_tools=["filesystem", "terminal", "beads_show", "beads_update"]
)
```

## 9. Что проверять после работы агентов
Координатор после завершения конвейера должен сам прочитать beads:
```text
beads_show("BD-CTX")
beads_show("BD-IMPL")
beads_show("BD-VERIFY")
```

Проверь, что:
- у контекстного bead есть структурированный вывод;
- у исполнительного bead есть итог и список сделанного;
- у верификационного bead есть PASS/FAIL и замечания;
- нет нерешённых проблем в notes.

## 10. Анти-паттерны
Нельзя:
- запускать нетривиальную задачу без beads-конвейера;
- запускать агента без `bead_id`;
- запускать агента без `beads_show` и `beads_update` в `executor_tools`;
- давать агенту задачу без указания, что читать и куда писать;
- доверять сложному результату без верификации;
- создавать beads после запуска агентов;
- передавать следующему агенту данные не через bead, а «на словах»;
- повторять неудачный вызов без изменения промпта или инструментов;
- использовать потенциально переполняющие контекст операции без необходимости.

## 11. Чеклист качества skill / процесса
Перед завершением проверь:
- [ ] Определена тривиальность или нетривиальность задачи.
- [ ] Для нетривиальной задачи создан конвейер через beads.
- [ ] Созданы все bead-задачи до вызова агентов.
- [ ] Между bead-задачами настроены зависимости, если они нужны.
- [ ] Каждый агент начинает с `beads_show()`.
- [ ] Каждый агент завершает записью через `beads_update()`.
- [ ] Есть этапы context → implement → verify.
- [ ] Координатор сам прочитал итоговые beads перед финальным ответом.
- [ ] Если были изменения файлов, результат проверен отдельным агентом.

## 12. Короткий пример end-to-end
```text
# 1. Создаём beads
bd_ctx = beads_create(title="Сбор контекста", type="task", priority=1, description="Изучить проект и записать контекст")
bd_impl = beads_create(title="Исполнение", type="task", priority=1, description="Выполнить задачу по контексту")
bd_verify = beads_create(title="Верификация", type="task", priority=1, description="Проверить результат")

# 2. Связываем зависимости
beads_dep(action="add", child_id=bd_impl.id, parent_id=bd_ctx.id)
beads_dep(action="add", child_id=bd_verify.id, parent_id=bd_impl.id)

# 3. Запускаем контекстного агента
orchestrate(... beads_show('CTX') ... beads_update('CTX', notes='[CONTEXT] РЕЗУЛЬТАТ: ...'))

# 4. Запускаем исполнителя
orchestrate(... beads_show('IMPL') ... beads_show('CTX') ... beads_update('IMPL', notes='[AUTHOR] РЕЗУЛЬТАТ: ...'))

# 5. Запускаем верификатора
orchestrate(... beads_show('VERIFY') ... beads_show('IMPL') ... beads_update('VERIFY', notes='[VERIFY] ВЕРИФИКАЦИЯ: PASS ...'))

# 6. Координатор читает итог
beads_show('CTX')
beads_show('IMPL')
beads_show('VERIFY')
```

## 13. Ключевой принцип
Если задача нетривиальна, координатор не должен «делать сам». Его работа — правильно декомпозировать задачу, создать beads, запустить подходящих агентов, получить проверенный результат и только потом выдать финальный ответ.
