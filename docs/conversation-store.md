# Хранилище чатов: файл на чат, миграция и откат

Чаты пространства хранятся в каталоге рядом с прежним единым файлом:
`<data>/conversations.json` → `<data>/conversations/` (`core/conversation_store.py`).
Каждый чат — отдельный файл `<id>.grc` (gzip). Если задан `GRID_SECRETS_KEY`, файл
дополнительно шифруется AES-GCM ключом, выведенным из него через HKDF.
Каталог считается полным, только если в нём есть `manifest.json`.

## Миграция (односторонняя)

При первом запуске новой версии сервер читает `conversations.json`, записывает
все чаты в каталог и переименовывает старый файл в
`conversations.json.migrated-<дата>`. С этого момента источник истины — каталог.
Версия без хранилища (например, `main` до этой ветки) каталог не читает, а
переименованный файл не находит: после простого отката чаты «пропадут».

## Ключ

- Файлы, зашифрованные ключом, которого у сервера нет (`GRID_SECRETS_KEY` не задан
  или задан другой), **останавливают запуск** пространства с ошибкой `KeyMissing`.
  Файлы при этом не трогаются: верните ключ и перезапустите сервер.
- Ротация: новый ключ первым, старые за ним через запятую — читаются все,
  шифрует первый.
- Потеря ключа означает потерю зашифрованных чатов. Храните его отдельно от
  резервных копий каталога.
- Повреждённый файл (ошибка gzip, неверная подпись при известном ключе)
  переносится в `<id>.grc.unreadable` и пишется в лог; остальные чаты загружаются.

## Откат на версию без хранилища

1. Остановите сервер.
2. Выгрузите каталог обратно в единый файл (с тем же `GRID_SECRETS_KEY` в окружении):

   ```bash
   python -m core.conversation_store export <data>/conversations <data>/conversations.json
   ```

   Команда не перезаписывает существующий файл.
3. Уберите каталог в сторону (`mv <data>/conversations <data>/conversations.store-backup`),
   иначе при повторном переходе на новую версию он снова станет источником истины.
4. Запустите прежнюю версию.

## Проекты

Проекты пространства лежат в `<data>/projects.json` (`web_chat/projects.py`).
Повреждённый файл переносится в `projects.json.unreadable-<дата>`, пространство
стартует без проектов (чаты показываются как «без проекта»). Чтобы восстановить,
остановите сервер, исправьте файл и верните ему имя `projects.json`.
