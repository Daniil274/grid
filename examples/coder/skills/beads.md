# Beads Issue Tracking

Используй beads как персистентный граф задач и handoff между агентами. Если в проекте нет `.beads`, сначала `beads_init(directory=...)` (обычно это выполняется автоматически для инженера).

## Выбор режима

- Простые вопросы и точечные правки 1–2 известных файлов выполняй напрямую.
- Для неизвестной подсистемы можно делегировать ограниченную разведку `Agent`, передав нужный контекст через `init_tools`.
- Средние/крупные задачи (несколько модулей, 3+ шага, исследование + реализация + проверка) разложи через `beads_plan` на задачи с критериями приёмки и зависимостями. Запускай готовую волну одним вызовом `parallel`, затем следующую после снятия блокеров.

`beads_plan(tasks=[{key, title, description, acceptance, depends_on, priority}])` создаёт план атомарно; результат содержит `ids`, `ready`, `waiting`. Используй зависимости, чтобы отделить разведку, реализацию и проверку. Не создавай искусственные beads для тривиальной работы.

## Параллельная работа и handoff

Используй `parallel(calls=[{tool, arguments, write_paths}])` для нескольких независимых вызовов, включая `Agent`, `WebSpider`, чтения и поиски. Для каждого исполнителя укажи область записи; `write_paths` не должны пересекаться. Чтения и независимый поиск можно выполнять вместе. Не передавай `beads_sync` подагентам; синхронизируй только по прямой просьбе пользователя.

Для задачи трекера передай исполнителю начальные вызовы до первого хода:

```json
[{"name":"beads_show","parameters":{"bead_id":"<id>"}},{"name":"beads_update","parameters":{"bead_id":"<id>","claim":true}}]
```

Кратко опиши в `input` результат и границы, не дублируя описание bead. Иной стартовый контекст (например, предварительное чтение файла) также можно передать через `init_tools`.

## Состояние, checkpoints и завершение

Исполнитель читает `=== CONTEXT [beads_show] ===` из `init_tools` и не вызывает повторно `beads_show` / `beads_update(claim=true)`, если задача уже загружена и взята в работу до старта. В ходе работы регулярно добавляет компактные checkpoints в `beads_update(bead_id, notes=...)`: выполненное, файлы, проверки и следующий шаг. Не закрывай незавершённую работу как успешную. В последнем ходе сохрани полный итог в notes и вызови `beads_close` в том же ответе только если критерии выполнены; иначе оставь задачу открытой и явно зафиксируй блокер.

После `timeout`/`max_turns` продолжай с новой задачей/исполнителем: передай через `init_tools` чтение старого bead и его notes, продолжай с checkpoint без повторной разведки. Не обходи `policy_deny`, `declined` или `policy_filter` другим агентом/инструментом.

## Инструменты

| Действие | Инструмент |
|---|---|
| Инициализация / готовое | `beads_init`, `beads_ready` |
| Поиск и просмотр | `beads_list`, `beads_show` |
| Создание и статус | `beads_create`, `beads_update`, `beads_close` |
| Граф зависимостей и план | `beads_dep`, `beads_plan` |
| Синхронизация (только по просьбе) | `beads_sync` |
| Общий журнал | `beads_log_append`, `beads_log_read` |

Пакетируй независимые операции одним ответом, но не запускай конфликтующие изменения одного bead одновременно.
