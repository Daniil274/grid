# CodeGraph

CodeGraph предоставляет семантический индекс текущей рабочей директории агента; MCP запускается с `add_working_directory: true` и `--path`. Индекс создаёт/обновляет идемпотентный function-инструмент `init_codegraph` для инженера; не трать отдельный shell-вызов на `codegraph init -i`. Если индекса нет или он устарел, инженер может вызвать `init_codegraph`.

## Выбор инструмента

| Задача | Инструмент |
|---|---|
| Найти символ по имени | `codegraph_search` |
| Понять подсистему/архитектуру | `codegraph_context` |
| Кто вызывает символ | `codegraph_callers` |
| Что вызывает символ | `codegraph_callees` |
| Влияние изменения | `codegraph_impact` |
| Детали символа / структура / статус | `codegraph_node`, `codegraph_files`, `codegraph_status` |
| Точный текст и regex | `grep_tool` |
| Файлы по шаблону | `glob_tool` |

Предпочитай CodeGraph для символов и связей, grep/glob — для точного текста и поиска файлов. Сверяй важные выводы с исходными файлами перед изменением.

## Контекстная эффективность и параллельность

Лёгкие lookup-вызовы допустимы в основной сессии. Широкий `codegraph_context` и исследование множества файлов передавай `Agent`, чтобы не засорять основной контекст; в поручении укажи требуемые символы, глубину и формат краткого отчёта с путями/ссылками на доказательства. Стартовые вызовы и известный контекст передавай через `Agent(input, init_tools=None)`, например предварительное чтение файла или поиск.

Независимые поиски, чтения и вызовы подагентов запускай одной волной через `parallel(calls=[{tool, arguments, write_paths}])`. Для читателей указывай пустые `write_paths`; пишущим агентам назначай непересекающиеся пути. MCP `codegraph` через `parallel` не вызывается. Если работа нетривиальная, координируй волны через `beads_plan`, фиксируй checkpoints в notes и не повторяй разведку после прерывания — продолжай с сохранённого checkpoint.
