# Coordinator Pipeline Example

Пример автономного агентского пайплайна на базе Grid с координатором, который строит конвейеры из динамических агентов через `orchestrate`.

## Идея

**Координатор не делает работу сам.** Он:
1. Декомпозирует задачу
2. Запускает агентов-исследователей (параллельно)
3. Синтезирует спецификацию на основе находок
4. Запускает агента-исполнителя
5. Запускает агента-верификатора
6. Выдаёт пользователю проверенный результат

Этот подход основан на двух источниках:
- **Claude Code Coordinator Mode** (`workspace/openclaude/src/coordinator/coordinatorMode.ts`) — мощный промпт для оркестрации задач через workers
- **Grid orchestrate** (`tools/orchestrator_tools.py`) — мета-инструмент для запуска динамических агентов

## Агенты

### Coordinator (главный)

Модель: `claude-sonnet-4-6` (Anthropic)

**Инструменты:**
- `orchestrate` — мета-инструмент для запуска динамических агентов
- Все инструменты из `claude-tools`: `bash_tool`, `file_read`, `file_write`, `file_edit`, `file_append`, `glob_tool`, `grep_tool`, `web_fetch`, `web_search`, `notebook_read`, `notebook_edit`, `notebook_create`, `todo_write`, `todo_list`, `todo_delete`, `todo_clear`
- `Agent` — general-purpose субагент
- `WebSpider` — веб-исследователь

**Системный промпт:** основан на Claude Code Coordinator Mode. Определяет:
- Роль координатора (не исполнителя!)
- 5-фазный пайплайн: Decomposition → Research → Synthesis → Implementation → Verification
- Правила написания самодостаточных промптов для агентов
- Стратегии параллельного и последовательного запуска
- Стандарты качества и анти-паттерны

### General-purpose (субагент)

Модель: `deepseek-v4-pro-opencode`

Используется через `Agent` tool для широких исследовательских задач и сложных многошаговых операций.

### Web Spider (субагент)

Модель: `kimi-k2.6-opencode`

Используется через `WebSpider` tool для поиска в интернете, обхода страниц и сбора фактов.

## Пайплайн

### Стандартный цикл

```
Пользователь → Координатор → [Исследователи] → Синтез → [Исполнитель] → [Верификатор] → Ответ
```

### Фазы

| # | Фаза | Кто | Инструмент |
|---|------|-----|-----------|
| 1 | Декомпозиция | Координатор | Мозги |
| 2 | Исследование | Агенты (параллельно) | `orchestrate` + file_read/glob/grep |
| 3 | Синтез | Координатор | file_read, анализ |
| 4 | Имплементация | Агент | `orchestrate` + file_edit/bash |
| 5 | Верификация | Агент | `orchestrate` + bash (тесты) |

## Запуск

```bash
# Из корня проекта grid
python main.py --config examples/coordinator-pipeline/config.yaml
```

## Переменные окружения

Скопируйте `.env.example` из `examples/claude-tools/` (или корня проекта) и заполните:

```bash
# Для coordinator (Anthropic)
ANTHROPIC_API_KEY=sk-ant-...

# Для workers (OpenCode)
OPENCODE_API_KEY=...

# Опционально: для web_search
FIRECRAWL_API_KEY=fc-...
```

## Примеры задач

### 1. Исследование кодовой базы

```
Пользователь: Найди все точки входа API в этом проекте и опиши их
```

Координатор запустит 2-3 исследовательских агента параллельно (по разным директориям), синтезирует результаты и вернёт структурированный отчёт.

### 2. Исправление бага

```
Пользователь: Исправь баг — при пустом поле email форма крашится с 500 ошибкой
```

Пайплайн: исследование (где форма, где валидация) → синтез (план исправления) → имплементация → верификация (тесты + проверка edge cases).

### 3. Рефакторинг

```
Пользователь: Вынеси логику работы с БД из контроллеров в отдельный слой
```

Пайплайн: исследование (все контроллеры с БД-запросами) → синтез (архитектура нового слоя) → имплементация → верификация.

### 4. Анализ документации

```
Пользователь: Сравни подходы к кэшированию в Redis и Memcached для нашего случая
```

Координатор запустит WebSpider для сбора документации и исследовательского агента для анализа текущего кода, затем синтезирует рекомендацию.

## Ключевые принципы

1. **Координатор не исполнитель.** Его работа — декомпозиция, синтез и управление.
2. **Каждый агент получает самодостаточную задачу.** Никаких «см. предыдущие находки».
3. **Синтез — главная добавленная ценность.** Не delegируй понимание.
4. **Параллельность — суперсила.** Исследовательские агенты работают одновременно.
5. **Верификация обязательна.** Никакой результат не принимается на веру.

## Отличия от ISKOR-autotest

| | ISKOR-autotest | coordinator-pipeline |
|---|---|---|
| Назначение | UI тестирование прибора | Универсальные инженерные задачи |
| Агенты | Статические (ui_tester, screen_analyzer) | Динамические (через orchestrate) |
| Пайплайн | beads-based конвейер | Координатор-управляемый |
| Инструменты | Специализированные (serial, скриншоты) | Универсальные (claude-tools) |
| Модели | Vision (qwen-vl) | Текстовые (Sonnet, Kimi, DeepSeek) |
