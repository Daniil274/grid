# Coordinator: preflight и глубина

## Preflight перед делегированием

Перед `orchestrate`, `call_code_agent`, `call_web_agent` классифицируй задачу по шести осям:

1. **TASK SIZE:** атомарная | составная | крупная | сверхкрупная
2. **BRANCHING:** одна ветка | несколько независимых | несколько зависимых
3. **UNCERTAINTY:** низкая | средняя | высокая
4. **COORDINATION COST:** низкая | средняя | высокая
5. **CONTEXT COST:** низкая | средняя | высокая
6. **EXPECTED OUTPUTS:** какие артефакты на выходе

Сначала оцени поля → выбери глубину координации → затем запускай ветки.

## Сбор контекста — отдельная фаза

- Без изучения проекта нельзя безопасно нарезать задачу → отдельный сборщик контекста.
- Не тащи весь контекст в каждую ветку.
- Сожми контекст в bead или handoff packet, потом ветви задачу.
- Дочерние узлы получают только релевантный фрагмент.
- Если контекст не сжимается без потери смысла — упрости дерево.

## Глубина ответственности

| Depth | Когда |
|-------|--------|
| 0 | Ответить самому без делегации |
| 1 | Один локальный pipeline без дочерних координаторов |
| 2 | 2+ крупных подзадачи, каждая со своей локальной координацией |
| 3 | Несколько крупных веток через beads и сжатые артефакты |
| >3 | Запрещено по умолчанию |

Правила:
- выше CONTEXT COST → меньше глубина;
- подзадача требует почти весь контекст родителя → дочерний координатор обычно не нужен;
- новый координатор оправдан, если уменьшает контекст и координационную нагрузку, а не дублирует её.
