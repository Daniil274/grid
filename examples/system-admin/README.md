# System Administrator

Система Grid, которая создаёт новые системы и улучшает существующие, включая сам
Grid. Работает только в **мастерской**: в контейнере со своим клоном ветки
`stable` из репозитория эволюции контроллера. Каждое изменение проходит как
эксперимент. Кандидата оценивает независимый контроллер `grid_control`, а в
`stable` его переносит оператор.

```
мастерская (контейнер)          контроллер (хост)                оператор
control_begin  ── bundle stable ◄─ GET /source
правки специалистов
control_trial  ── снимок работы ──► POST /trials → открытые сценарии, подробности
control_submit ── bundle кандидата ─► refs/candidates/<sha> → закрытые сценарии в Docker
control_status ◄──────────────────── accepted / rejected / failed
                                     grid-control promote <id> ◄── подтверждение
                                     stable → кандидат
```

## Агенты

| Агент | Роль | Инструменты |
|---|---|---|
| `administrator` | Вход системы. Ставит задачу и критерий успеха, открывает эксперимент, поручает изменение специалисту, проверяет его и отправляет кандидата | каталог и проверка систем, чтение файлов, история git, `control_*` (begin, diff, revert, scenarios, trial, submit, status), вызов специалистов |
| `architect` | Проектирует и пишет новую систему по образцу существующих и регистрирует её в `routing.yaml` | каталог и проверка систем, чтение, точечная правка, создание и удаление файлов, `control_diff` |
| `improver` | Находит причину провала существующей системы и вносит минимальную правку | каталог и проверка систем, чтение, точечная правка, создание и удаление файлов, `control_diff` |

Администратор файлы не правит; специалисты видят только `control_diff` (чтение), git и
остальные `control_*` им недоступны. Ни у
кого нет инструментов коммита: коммит, bundle и отправку делает только
`control_submit`, и только в репозитории, помеченном как мастерская
(`grid.workshop=true`). В любом другом репозитории инструменты `control_*`
отказываются работать.

| Скилл | Кому | О чём |
|---|---|---|
| `skills/grid-system.md` | всем | устройство системы: каталог, `config.yaml`, типы инструментов, описания для роутера, регистрация |
| `skills/experiment.md` | администратору | цикл begin → изменение → проверка → trial → submit, статусы, границы |
| `skills/diagnosis.md` | улучшателю | где искать причину провала и как её доказать |
| `skills/editing.md` | специалистам | точечная правка (`file_replace`, `file_edit_patch`), чего не делать с файлами |

## Инструменты

- `tools/grid_systems_tools.py`: `grid_systems_catalog` и `grid_check_system`
  (та же проверка, что выполняет роутер при старте). Только читают.
- `tools/control_tools.py`: `control_begin`, `control_diff`, `control_revert`,
  `control_scenarios`, `control_trial`, `control_submit`, `control_status` поверх
  `core/workshop.py`. `control_diff` сравнивает всю работу с baseline (а не с
  последним коммитом), `control_revert` возвращает файлы к baseline.
- `tools/file_tools.py`: `file_replace` (точная замена фрагмента),
  `file_edit_patch` (unified diff, блоки ищутся по контексту), `file_write`,
  `file_delete`. Переводы строк файла сохраняются, содержимое `.git` менять
  нельзя.
- Служебные файлы администратора (`.grid/`, `logs/`, базы данных, кэши) в
  кандидата не попадают: мастерская исключает их в `.git/info/exclude`. SHA агент не
  видит и не вводит, их вычисляет мастерская. `control_trial` прогоняет
  незавершённую работу на открытых сценариях и показывает подробности, а
  приёмка идёт на закрытом наборе (`docs/self-improvement.md`).

## Запуск

Установка и настройка контура целиком (образы, репозиторий эволюции, политика и
сценарии, токен, контроллер, мастерская, выкатка, обслуживание) описаны в
[docs/evolution-setup.md](../../docs/evolution-setup.md). Коротко:

```powershell
grid-control init --repo C:\grid-evolution\evolution.git --from . --ref HEAD
grid-control --state C:\grid-evolution\experiments.db serve --repo C:\grid-evolution\evolution.git --policy C:\grid-evolution\policy.json --port 8010
docker compose --profile evolution up -d workshop     # http://localhost:8001
grid-control --state C:\grid-evolution\experiments.db promote <id>
```

В роутере хоста (`routing.yaml`) этой системы нет намеренно: она меняет Grid и
не должна работать с рабочей копией.

## Примеры запросов

- «Сделай систему для разбора PDF-счетов: извлечь реквизиты и суммы в таблицу».
- «Роутер отправляет вопросы про ffmpeg в engineering вместо video. Почини».
- «Агент desktop не может закрыть окно — добавь ему это действие».

## Ограничения

- `accepted` значит, что кандидат прошёл проверки и сценарии оператора не хуже
  baseline. Сценарии проверяют маршрут, вызванные инструменты и ответ, но не
  качество работы целиком: что не описано в сценариях, то не оценено.
- Логи рабочей установки мастерской не видны. Диагностика опирается на
  доказательства из запроса.
- Новые зависимости Python и внешние программы требуют от оператора нового
  runtime. Система только сообщает о такой необходимости.
