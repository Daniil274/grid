# Правка файлов

Твоя правка уходит в коммит кандидата целиком, и её читает администратор.
Каждый лишний байт — шум в diff или риск сломать соседнюю систему.

## Инструменты

| Задача | Инструмент |
|---|---|
| Заменить фрагмент: описание, строку промпта, элемент списка | `file_replace(filepath, old_text, new_text)` |
| Несколько мест одного файла | `file_edit_patch` с блоками `@@`, строки ` ` / `-` / `+` |
| Новый файл | `file_write` |
| Удалить файл, созданный по ошибке | `file_delete` |
| Посмотреть свои изменения против baseline | `control_diff` |

- `old_text` копируй из только что прочитанного файла дословно, с отступами.
  Если инструмент ответил «not found» или «occurs N times», перечитай нужное
  место (`file_content_search` покажет номер строки) и повтори с точным или
  более длинным фрагментом.
- Существующий файл не переписывай через `file_write` ради небольшой правки:
  так меняются все строки, переводы строк и форматирование.
- Инструменты сохраняют переводы строк файла сами. YAML после правки должен
  оставаться корректным: проверь `grid_check_system`.

## Чего не делать

- Не создавай пробных и временных файлов для экспериментов с инструментами.
  Если создал — удали через `file_delete`.
- Не трогай файлы и поля вне брифа. Нужна правка в другом месте — опиши её в
  отчёте, администратор решит.
- Не пиши код, который что-то делает при импорте или загрузке, и не используй
  код как обход ограничений инструментов (удалить файл, выполнить команду,
  прочитать чужое). Если инструмента не хватает — остановись и скажи об этом.
- Не читай `.git`, логи и базы данных в поисках старых версий файлов:
  `control_diff` показывает всё, что изменено против baseline.

## Готово, когда

`grid_check_system` — `healthy: true` для каждой изменённой системы,
`control_diff` показывает только файлы из брифа, и последним сообщением ты
вернул текстовый отчёт.
