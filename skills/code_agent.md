# Протокол старта задачи
Перед любой работой с кодом выполни три шага:
1. memory_search — найди прошлые решения, паттерны, договорённости, ограничения среды, связанные с задачей.
2. skill_search — найди навык, если задача типовая (рефакторинг, тесты, миграция и т.д.).
3. Изучи структуру кода: сначала список файлов, потом читай только то, что необходимо.
   Не читай файлы целиком без причины.

# Семантический поиск
- Используй semantic_search_code(query, directory) для навигации по незнакомой кодовой базе
  или когда не знаешь, где именно искать реализацию.
- Перед первым поиском убедись, что индекс создан: index_codebase(directory).
- Запросы пиши на языке концепций, не ключевых слов: "обработка входящих событий" лучше чем "event handler".

# Рабочий цикл (Read → Understand → Plan → Implement → Verify)
1. Read: прочитай только непосредственно затрагиваемые файлы и их зависимости.
2. Understand: сформулируй про себя, что делает текущий код и почему задача требует изменений.
3. Plan: реши, какие файлы и как изменить. Для нетривиальных задач изложи план явно.
4. Implement: вноси минимально необходимые изменения. Не рефакторь код вне скоупа задачи.
5. Verify: после изменений запусти тесты или проверочные команды, убедись что ничего не сломано.

# Работа с памятью
- После завершения задачи сохрани в память: ключевые архитектурные решения, нетривиальные находки,
  паттерны, которые будут полезны при следующей похожей задаче.
- Сохраняй конкретные факты, а не пересказ — одна запись = одна чёткая мысль.
- Теги: язык/фреймворк, тип паттерна, модуль (например: python, async, auth_module).
- Не дублируй уже существующие записи — сначала memory_search, потом memory_save.

# Работа с навыками
- Если решил нетривиальную задачу повторяемым способом — сохрани как skill_save.
- Навык = пошаговая инструкция или шаблон, применимый в будущем без лишнего контекста.

# Правила кода
- Не изменяй поведение существующих функций сверх задания.
- Не добавляй зависимости без необходимости.
- Не оставляй закомментированный код и отладочный вывод.
- Если задача неоднозначна — уточни до начала реализации, а не в середине.
