# Docs Ops

Команда из четырёх агентов для документации в рабочей папке. Тексты — только стандартная библиотека; PDF — `fpdf2` + `olefile` (ставятся до отключения сети) со stdlib-фолбэком.

## Агенты
- `main` (координатор, единственный routable): разбирает запрос, вызывает исполнителей через agent-вызовы, затем обязательно независимую проверку, отчитывается с вердиктом. Сам файлы не правит.
- `writer`: тексты, правки, TOC, терминология, Markdown/HTML/CSV. Единственный владелец изменяемых текстов в своей подзадаче.
- `converter`: `extract_text`, `convert_to_pdf`, `md_to_pdf` офлайн + `soffice` для точного макета. Исходники не трогает.
- `reviewer`: независимый, только чтение. Проверяет артефакты сам, возвращает PASS/FAIL.

## Что умеет
- Писать и точечно править README, гайды, справки, changelog.
- Проверять: `doc_lint`, `check_links`, `term_check`, `doc_stats`, `doc_inventory`, `doc_outline`.
- Оглавление `update_toc` (идемпотентно).
- Конвертация текстов: Markdown ↔ HTML, txt → Markdown, CSV ↔ таблицы.
- PDF офлайн: `extract_text` (txt/md/csv/html/docx/legacy .doc), `convert_to_pdf`, `md_to_pdf` → `<name>.pdf` рядом. Латиница всегда; кириллица при Unicode-TTF (DejaVuSans/Liberation/Noto), иначе `?` с предупреждением. Точный макет Word — через `soffice --headless --convert-to pdf`.

## Примеры запросов
- «Преобразуй guide.md в HTML со встроенным CSS».
- «Добавь оглавление в README.md и проверь ссылки».
- «Приведи термины в docs/ к единому виду: email вместо e-mail».
- «Сконвертируй table.csv в таблицу Markdown».
- «Извлеки текст из uploads/manual.doc и сконвертируй в PDF».
- «Сконвертируй guide.md в PDF».

## Вход и выход
Вход: запрос + файлы, включая `uploads/` (md, html, txt, rst, csv, doc, docx). Выход: файлы от исполнителей + отчёт координатора: кто что делал, вердикт проверки, ограничения.

## Ограничения
- Внешние URL не проверяются.
- Markdown → HTML — распространённое подмножество, не весь CommonMark.
- Офлайн-PDF читаемый, не pixel-perfect: без таблиц Word/картинок/колонтитулов; кириллица без Unicode-TTF → `?`. Для точного макета нужен `soffice`.
- Legacy .doc читается как текст, форматирование не сохраняется.
- Нужна `OPENCODE_API_KEY` для моделей.
