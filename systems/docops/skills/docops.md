# Протокол Docs Ops

## Вход и выход
Вход: любая просьба про документы рабочей папки. Выход: изменённые/созданные файлы и краткий отчёт. Нет входного файла — скажи об этом (FILE_NOT_FOUND) и ничего не создавай.

## Конвертация в PDF (офлайн, без сети)
Приоритет — встроенные инструменты пакета `doc_tools`, они работают без сети:
1. `extract_text(path)` — проверь, что источник читается (txt/md/csv/html/docx/legacy .doc). Для `uploads/*.doc` сначала вызови его и покажи объём/превью.
2. `convert_to_pdf(path)` — универсально для txt/md/csv/html/docx/doc. `md_to_pdf(path)` — для Markdown (разметка stripped, заголовки как текст).
3. Оба создают `<name>.pdf` рядом с исходником, не перезаписывают существующий без `overwrite=true`, исходник не удаляют.
4. Латиница работает всегда (fpdf2, иначе stdlib-минимальный PDF). Кириллица требует Unicode-TTF в контейнере (DejaVuSans/Liberation/Noto) — если его нет, инструмент вернёт понятную ошибку: назови её и предложи `soffice --headless --convert-to pdf`.
5. Проверь результат: файл существует, размер > 0, начинается с `%PDF`. Прочитай исходник повторно — он должен остаться нетронутым.

## Терминал и бинарные форматы (pixel-perfect layout)
Если нужен точный макет Word (таблицы, колонтитулы, картинки), а не простой читаемый PDF:
1. Проверь: `which soffice libreoffice pandoc`.
2. `soffice --headless --convert-to pdf --outdir <dir> "<file>"`; если нет soffice — pandoc; если нет — попробуй `pip install --user ...` (может быть запрещено политикой).
3. Отказ допустим только после реальных попыток: приведи команды и текст ошибок и назови, что именно нужно поставить.
Файлы пользователя лежат в `uploads/`; результат клади рядом с исходником.

## Порядок для текстовых документов
1. **Разведка.** Незнакомая папка — `doc_inventory`. Один документ — `file_read`, при необходимости `doc_stats`, `doc_lint`.
2. **Правка.** Один владелец файла — ты. Меняй точечно (`file_replace`, `file_edit_patch`); целиком переписывай только новые файлы. Не выдумывай факты, команды, версии; недостающее помечай `TODO:` и называй в отчёте.
3. **Конвертация текстовых форматов.** `md_to_html`, `html_to_md`, `text_to_md`, `csv_to_md_table`, `md_table_to_csv` создают новый файл рядом и не перезаписывают существующий. `overwrite=true` — только по просьбе. После конвертации прочитай результат и проверь структуру.
4. **Оглавление.** `update_toc` идемпотентен (`<!-- toc -->`…`<!-- tocstop -->`), меняет файл на месте — только если оглавление запрошено.
5. **Терминология.** `term_check`, правь точечно (код не трогай), повтори — должно быть 0.
6. **Проверка.** После правок `doc_lint` и `check_links` для затронутых Markdown-файлов; постороннее перечисли, не чини без просьбы.
7. **Повтор.** Перед повторным действием проверь текущее состояние; не дублируй разделы и файлы.

## Стиль технических текстов
Одна H1, заголовки без пропусков уровней и без точки; блоки кода с языком; императив в инструкциях; короткие предложения; единая терминология; списки с `-`; файл заканчивается переводом строки. Язык — исходника или запроса.

## Отчёт
Что сделано; файлы (созданы/изменены); результаты проверок; что не проверено. При ошибке — процитируй причину и предложи следующий шаг. Для PDF всегда указывай движок/ограничение (unicode-ttf, core-latin, stdlib) и что кириллица без TTF заменяется на `?`.
